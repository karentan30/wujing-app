## 🔴 必须修复才能上线（阻塞项）

### 安全部门

**S5 — 文件上传无 magic byte 校验（RCE 风险）**
- `/api/decompose` 只检查 HTTP 头 Content-Type，`/api/upload` 完全不检查
- 攻击者可将恶意脚本加 `Content-Type: video/mp4` 上传到 DATA_DIR，若 Web Server 误执行则 RCE
- 修复：读取 `content[:12]`，校验 MP4/MOV/AVI 文件头（ftyp box 或 RIFF）；同时确认 DATA_DIR 不在 Web Server document root 下

**S11 — 两处 XSS（class_join + class_teacher）**
- `class_join.html` 第 276 行：`$('rNote').innerHTML = '老师评语：<br>'+s.teacher_note`，teacher_note 来自 DB 未转义，老师账号提交含 `<script>` 评语即可在学员浏览器执行任意 JS
- `class_teacher.html` 第 207-215 行：`m.nickname`、`m.real_name` 直接插入模板字面量未 HTML 转义，学员注册填入恶意昵称可 XSS 攻击老师端
- 修复：全站引入统一 `_esc()` 函数（design-upgrade.html 已有，复用即可），所有动态字符串插入 innerHTML 前必须转义

### QA 部门

**T5 — /api/pay/wechat/create 鉴权顺序错误**
- 无 token 请求返回 422/400（body 校验先于 auth），而非 401/403
- 攻击者可探测接口参数结构
- 修复：将 auth middleware 移到 body validation 之前，无 token 直接 401

**T9 — /api/health 响应持续 3.5-8 秒（严重超标）**
- 多次测试：7.1s / 1.4s / 8.2s / 5.6s / 3.5s / 4.5s，远超 2 秒门槛
- 疑似 2 核 HK 服务器被 ffmpeg/mediapipe 拖死，或 health endpoint 有 DB 查询
- 修复：排查 health endpoint 是否含 DB 查询；加 `/ping` 纯内存响应端点供监控用；排查服务器资源占用

### PM 部门

**支付链路真人验收（硬性阻塞）**
- 交接文档明确写"从未真实收过一单"，WJ_FREE_MODE=1
- 上线前 Karen 必须真人扫码付 ¥9.9 一单，确认回调→fulfilled→拆解全链路，验证通过后再切 WJ_FREE_MODE=0

### CTO 部门

**T5 — auto_decompose._run() 无超时**
- `_run()` 函数调用 `subprocess.run` 无 timeout 参数，被 `_dur/_grab/_clip` 四处调用
- 处理大视频时 ffmpeg 可无限阻塞后台线程直至 OOM
- 修复：改为 `subprocess.run(cmd, capture_output=True, text=True, timeout=300)`

## 🟡 上线后尽快（非阻塞）

### 安全部门

- **S12 — 免费配额设备指纹可绕过**：`_free_quota_ok()` 基于客户端自报 X-Device-ID，攻击者换 UUID 即可无限绕过，持续烧 ARK/DeepSeek 余额。WJ_FREE_MODE=1 时高危。建议：identity 改为 device_id+IP 联合 key
- **S2 附 — 微信签名算法弱**：使用 MD5（APIv2），微信官方已推 APIv3 + RSA，建议规划升级
- **S6 附 — JWT 默认 Secret 不一致**：auth.py fallback='wujing-jwt-secret-change-in-production'，pay.py fallback='wujing-secret-change-me'，两个 secret 不一致；若生产未设环境变量则任何人可伪造 token，且 pay.py 的 get_credits/consume_credit 会验签失败
- **S8 — 异常详情部分泄露**：server.py 第 117 行把 JWT 库内部错误字符串返回客户端；第 494 行把 ARK API 原始报错返回前端。建议统一替换为通用错误消息

### QA 部门

- **Q_ENCODE — Content-Type 缺 charset 声明**：返回 `application/json` 未包含 `charset=utf-8`，轻微不规范，建议补全
- **T10 — 重定向码 308 非 301**：Caddy 默认 308，部分老客户端/爬虫可能只认 301，功能等价但建议确认

### CTO 部门

- **文件上传先全量 read 再校验**：`content = await video.read()` 将全部内容读入内存后才校验 500MB，极端情况内存压力先到。建议改为流式读取+边读边计数
- **generate-bg 内存泄漏风险**：`_bg_daily` 字典仅在 len>2000 时整体清空，高并发下清空时丢失当日配额状态
- **T9 systemd Restart 参数未在本地验证**：建议 `ssh root@47.242.80.65 'systemctl cat wujing-api'` 确认 Restart 值是否为 on-failure
- **get_db() 为短连接非连接池**：高并发下有 busy_timeout 风险，中期考虑升 PostgreSQL
- **auth.py decode_token 异常消息暴露**：get_current_user 在 401 detail 中返回 str(e)，可能泄漏 JWT 库内部错误信息
- **支付宝回调未验证 app_id 字段**：仅验 RSA2 签名和 trade_status，未校验 app_id 是否与配置一致

### PM 部门

## 乱码问题专项

**当前结论：无中文乱码问题。**

QA 部门已验证：
- `GET /api/teachers` 响应为原始 UTF-8 字节（无 \u 转义），"比心手势舞"/"刀马刀马"/"BABYMONSTER" 等中文字段正确显示
- Content-Type 返回 `application/json`（未含 charset=utf-8 声明，但实际编码正确）

**唯一注意点**：Content-Type 未声明 charset=utf-8（QA 黄灯），属轻微不规范，建议补全 `application/json; charset=utf-8`，但不会导致乱码——FastAPI 默认 UTF-8 编码，现代浏览器和客户端均可正确解析。无需为此阻塞上线。
