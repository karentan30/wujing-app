# 舞镜 · 达人分销接入方案（0729）

> 目标：达人推舞镜链接 → 用户点入 → 注册/付费时归因到达人 → affiliate 后台按比例算佣金。
> 本文档是纯设计+清单，不含任何生产文件改动。

---

## 一、affiliate 后台现状（~/projects/affiliate）

### 技术栈
- **backend/server.js**：Express + better-sqlite3，端口 3020，已有完整 REST API
- **lib/track.js**：前端埋点脚本（一行引入）
- **dashboard.html**：达人自助查看数据面板（金色风格）
- **index.html**：达人申请入口表单

### 三张核心表
| 表 | 用途 |
|---|---|
| `affiliates` | 达人档案：ref_code / status(pending→approved) / total_clicks / total_orders / total_commission |
| `affiliate_clicks` | 每次点击记录（ref_code + product + IP + UA） |
| `affiliate_commissions` | 每笔佣金：order_amount / commission_amount / status(pending→paid) |

### 已有 API（全部就绪）
- `POST /api/affiliate/signup` — 达人申请，自动生成 ref_code，发欢迎邮件+管理员通知
- `POST /api/affiliate/track-click` — 前端落地时报点击（静默，unknown code 不报错）
- `POST /api/affiliate/record-commission` — 后端付款成功时回调（幂等：同 order_id 只记一次）
- `GET /api/affiliate/dashboard/:ref_code` — 达人查看自己数据
- `POST /api/affiliate/withdraw-request` — 达人申请打款（发邮件给管理员）
- `GET /api/admin/affiliates` + `POST /api/admin/approve/:id` + `POST /api/admin/pay/:id` — 管理员后台

### 分成比例（硬编码）
当前 `commission_amount = order_amount * 0.2`，即 **20%**。金额单位：分（×100 存库）。

### 参数命名说明
- affiliate 后台用 `ref`（URL 参数）和 `aff_ref`（localStorage key）
- 舞镜/Lumee 生态习惯用 `xs_ref`（URL 参数）和 `xs_ref`（localStorage key）
- **接入方案统一兼容两者**：前端同时写 `aff_ref` 和 `xs_ref`，后端两个都接受

## 二、Lumee 做法参考（成熟实现，可复用思路）

Lumee 在 server.py 里的 affiliate 闭环（约 12760–12892 行）：

1. **落地记归因**：`GET /affiliate/{code}` → `_affiliate_record_landing(anchor, code)` → 写 `affiliate_attributions` 表（anchor=token/guest_token，支持窗口期）
2. **下单时读归因**：`_read_affiliate_code(body)` → ①先看 body 显式带的 affiliate_code → ②回查归因窗口兜底（末次触达）
3. **付款成功时记佣金**：`_affiliate_apply_commission(con, oid)` → 在 `_db_lock` 内幂等累计

舞镜方案**简化版**（affiliate 后台已有独立 DB，不需要在 wujing 的 SQLite 建额外表），只需：
- 前端落 localStorage
- 注册/付费时把 ref_code 带给 wujing 后端
- wujing 后端成功后回调 affiliate 后台

## 三、闭环设计（端到端）

```
达人 → 生成链接 https://wujing.mylumee.app/?xs_ref=WUJ1234
  ↓ 用户点入
前端 design-upgrade.html
  - URL 参数读 xs_ref / ref（兼容两种写法）
  - 写 localStorage: xs_ref=WUJ1234 + aff_ref=WUJ1234
  - 发 POST /api/affiliate/track-click（到 affiliate 后台端口 3020）
  ↓ 用户注册
/api/register_json（wujing FastAPI）
  - 从 body 读 ref_code（前端在请求 body 里带上 localStorage 里的值）
  - 注册成功后：POST affiliate后台 /api/affiliate/track-click（如未点过）
  ↓ 用户付费（接入支付后触发）
/api/payment/callback（支付成功回调）
  - 从订单记录的 affiliate_code 字段取出 ref_code
  - POST affiliate后台 /api/affiliate/record-commission（{ref_code, order_id, order_amount, product:"wujing"}）
  ↓ 对账
affiliate dashboard.html?ref=WUJ1234
  - 达人自助查看：点击数 / 成交数 / 待结算佣金
```

## 四、需要在 wujing 改的清单（精确到函数/字段）

### A. 前端 design-upgrade.html — 改动清单

**A1：落地捕获 xs_ref（新增，约20行）**
- 在 `<script>` 顶部（DOMContentLoaded 之前）加 `_captureAffRef()` 立即执行函数
- 逻辑：读 `URLSearchParams` 的 `xs_ref` / `ref` 参数 → 有值就写 `localStorage.setItem('xs_ref', val)` 和 `localStorage.setItem('aff_ref', val)`
- 同时 fire-and-forget `POST https://affiliate-api/api/affiliate/track-click` 带 `{ref_code: val, product: 'wujing'}`

**A2：注册请求带 ref_code（改 `handleAuth()` 函数）**
- 目前 handleAuth 里的 fetch body：`{ email, password }`
- 改为：`{ email, password, ref_code: localStorage.getItem('xs_ref') || '' }`

**A3：付费请求带 ref_code（改付费 fetch，等支付②做完再接）**
- 支付 body 里加 `ref_code: localStorage.getItem('xs_ref') || ''`
- 支付回调成功后清除：可选（末次触达模型下不清也行，避免二次购买丢归因）

### B. 后端 server.py — 改动清单（A 类，需重启）

**B1：/api/register_json — 接收 ref_code 字段并存库**
- 找到 `register_json` 路由处理函数
- 从 `body` 读 `ref_code = body.get("ref_code", "") or body.get("affiliate_code", "") or ""`
- users 表加字段：`ALTER TABLE users ADD COLUMN affiliate_code TEXT`（已存在则跳过）
- 注册成功时写入：`INSERT INTO users (..., affiliate_code) VALUES (..., ?)`
- 注册成功后异步回调 affiliate 后台 track-click（可选，前端已做就跳过）

**B2：新增 `_affiliate_http_callback(ref_code, order_id, order_amount)` 工具函数**
- 用 `urllib.request` 或 `httpx`（FastAPI 项目一般有）发 POST 到 affiliate 后台
- URL：`http://localhost:3020/api/affiliate/record-commission`（同机部署）或配 env `AFFILIATE_API_URL`
- body：`{ref_code, order_id, order_amount, product: "wujing"}`
- 失败只打日志，不影响主流程

**B3：付款成功回调处 — 触发佣金回调**
- 等支付②完成后，在支付成功落库处调用 `_affiliate_http_callback()`
- 从 users 表取该用户的 `affiliate_code`（注册时已存），或 body 显式带的 ref_code
- 幂等由 affiliate 后台保证（同 order_id 只记一次），wujing 不需额外处理

### C. 运维配置

**C1：affiliate 后台部署**
- 已有代码：`~/projects/affiliate/backend/server.js`
- 部署到 HK 服务器 47.242.80.65，端口 3020（参考 Slim 端口 3006 命名规范）
- PM2 启动：`cd /www/affiliate-api && pm2 start server.js --name affiliate-api`
- Caddy 可选反代（也可 wujing 直连 localhost:3020）
- 需要 env：`SMTP_HOST / SMTP_USER / SMTP_PASS / SMTP_FROM / ADMIN_EMAIL / ADMIN_SECRET / PORT=3020`

**C2：数据库路径**
- affiliate 后台 DB：`/data/affiliate.db`（服务器有 /data 时）或 `/www/affiliate-api/backend/affiliate.db`
- 与 wujing 的 SQLite 完全独立，无需合并

## 五、分成比例建议

| 达人粉丝量 | 建议分成 | 说明 |
|---|---|---|
| < 1万（KOC） | 20% | affiliate 默认值，维持 |
| 1-10万 | 25% | 手工在 admin 调高（当前 commissions 是后端算，可加 `commission_rate` 字段） |
| > 10万 | 30% | 单独谈，手工后台记录 |
| 服装品牌赞助合作 | 定制 | 三方合同，线下结算 |

**当前 affiliate 后台佣金率是全局硬编码 20%**，若要支持per-达人调比例，需在 affiliates 表加 `commission_rate REAL DEFAULT 0.2`，在 `record-commission` 路由读取该字段动态计算（清单：affiliate backend/server.js，第 245 行附近，约5行改动）。

## 六、达人招募链路（业务配合）

1. 达人访问 `wujing.mylumee.app/affiliate/`（alias affiliate 申请页 index.html）
2. 填写姓名/邮箱/小红书账号/粉丝量 → 提交
3. Karen 收邮件 → 点「一键审核通过」链接
4. 达人收欢迎邮件，含专属链接 `wujing.mylumee.app/?xs_ref=WUJ1234` 和 dashboard 链接
5. 达人发小红书/抖音带链接，用户点入
6. 月底达人在 dashboard 点「申请提现」→ 邮件通知 Karen 手工打款（微信/支付宝）
