# 舞镜 · 独舞 AI 点评整合方案（0730）

> **一句话**：个人上传自己跳的舞 → 舞镜 AI 逐段拆出「标准动作」→ 用户录/传自己跳的 → 舞镜 AI 逐帧对齐比对 → 出「76 分式点评 + 量化改正」。
> **诚实红线**：所有分数、角度、拍差都来自**舞镜 AI 姿态引擎的真实测量**（关节角度、时间偏移），**测不到就不编、降级说明**，绝不用随机模板凑数字。
> **技术脱敏**：对外一律叫「舞镜 AI」/「舞镜 AI 姿态引擎」，不出现 MediaPipe / SSIM / landmark 等底层词。

## 一、这条线在舞镜产品里的定位

老板定的 C 端独舞线 =「**想知道自己跳得好不好**」= AI 动作点评。它和已上线的「任意舞自动拆解」是**同一姿态引擎的两个出口**：

| | 已上线：无参考拆解 | 本方案：有参考点评（独舞线） |
|---|---|---|
| 用户动机 | 想学一支舞 → 拆成八拍卡跟练 | 想知道自己跳得好不好 → 对标打分 |
| 输入 | 一支舞（当教材） | 标准视频 + 自己跳的视频（两支） |
| 舞镜 AI 干的事 | 逐段描述 + 单帧角度点评 | 逐段**对齐比对**标准 vs 自己 → 差值 |
| 产物 | 八拍卡 / 故事卡 / 记忆卡 | **76 分点评报告**（review-demo.html） |
| 复用 | `auto_decompose.py` | 复用其拆段 + `pose_angles.py`，新增比对层 |

**关键关系**：独舞点评 = 「拆解」先把标准拆成带角度的分段 → 再把用户跳的按同样分段测角度 → 两组角度/拍点做差 → 差值驱动 76 分报告。**不是新引擎，是拆解引擎接一个「比对层」。**

## 二、用户流程（端到端 5 步）

```

(或选已拆的      每段存"标准角度      录制或上传        标准角度 − 我的角度    +量化改正
 教材/老师)      指纹")             自己的视频        =偏差(°/拍)          +时间轴+亮点
```

**三种入口，同一比对内核：**
1. **A 入口（老师/教材对标）**：用户选一个平台已拆好的舞（老师版 / 自己此前拆过的舞）当标准 → 只需上传自己跳的一支 → 直接进第 ④ 步。（最省钱，标准角度已缓存）
2. **B 入口（自带标准）**：用户上传两支——标准视频 + 自己跳的 → ② 先拆标准 → ④ 比对。
3. **C 入口（同一支舞复练进步曲线）**：用「上一次自己跳的」当标准，看这次比上次进步多少。（留存钩子）

**上传体验（诚实前置约束）：**
- 上传页明确提示：**全身入镜 / 光线充足 / 单人 / 竖屏建议**——姿态引擎测不准就无法给真实分数（把约束前移，避免出废报告，照 GPU 约束前移铁律）。
- 时长/风格自动识别，不让用户填。

## 三、比对内核：76 分与量化数字怎么保证真实

**这是整个方案的诚实命门。** 现成 `wujing-analyze.py`（老 `analyze.py`）用的是**像素差 SSIM + 随机挑模板文案**——那是会编数字的假点评，**本方案明确弃用它的评分与文案逻辑**，改由姿态引擎实测驱动：

### 3.1 分数从哪来（全部实测，可回溯）
对标准和「我的」在**每一对同段关键帧**上，用 `pose_angles.py` 各测一组关节角度（右肘/左肘/右肩抬臂/左肩/右膝/左膝/右髋/左髋 + 躯干倾斜），逐关节做差：

- **动作延展度分** = 由各关节角度偏差 |标准° − 我的°| 归一化。例：右肘标准 170°、我的 132° → 差 38° → 这一拍这个关节扣分有据。
- **镜像一致性分** = 左右对称关节的角度镜像差（同一姿态左右臂该对称时差多少）。
- **节拍契合度分** = 用户段的「最大幅度帧」时间 vs 标准段最大幅度帧时间的偏移 → 折算成「拍」（结合 BPM），例「结尾比标准提前约 1 拍」= 真实时间差 ÷ 每拍时长。
- **情感表达力**：**诚实降级**——姿态引擎测不了情感。这一维不编分，改由 vision（舞镜 AI 看画面）给**定性**评价（眼神/含胸/下巴），或**直接标注「此维为 AI 观察参考，非测量分」**。宁可少一维硬指标，也不假装能测情感。
- **总分（如 76）** = 可测维度加权平均，**明确是"可测维度综合"**，不是玄学总评。

### 3.2 诚实四原则（写进引擎，不是口号）
1. **测不到就说测不到**：某帧检测不到骨架（暗场/遮挡/多人/半身）→ 该帧不产出角度、不产出分，报告里标「此段画面无法测量」，绝不用邻段或模板顶替。（引擎已有 `visibility ≥ 0.55` 门槛 + 暗场提亮重试，沿用）
2. **数字必须可回溯**：报告里每个「38°」「提前 1 拍」都能对应到 `angles.json` 里标准/我的两个实测值 + 帧时间戳。前端「问题卡」展开时可显示「标准 X° / 你 Y°」两个真数字并排。
3. **文案引用真数字，不写空泛套话**：复用 `_vision_coach` 的铁律 prompt（禁"身形舒展/很有美感/继续加油"），并把实测差值喂进去，让改正建议 = 部位 + 当前 X° + 目标 Y° + 怎么改。
4. **低置信不给高分**：整支可测帧比例过低（如 < 40%）→ 不出总分，出「本次拍摄多数画面测不准，建议重拍（全身/光线）」，把重拍按钮顶上来。

### 3.3 与老 analyze.py 的处置
- 老 `analyze.py` 的 `compare_frames`（SSIM 像素差）+ `generate_feedback`（`_PROBLEM_TEMPLATES` 随机模板）**整块废弃**，不接入独舞线。
- review-demo.html 里的示例文案（"比老师提前1拍""弓步只弯120°"）是**目标形态样例**，真实报告由引擎填真值，形态一致但数字实测。

## 四、前端怎么接（复用 review-demo.html）

review-demo.html 的 UI 结构已经就是目标形态，接线改动小：

1. **数据驱动化**：把写死的 76 / 四维 / 5 问题卡 / 2 亮点 → 改为读 `GET /api/review/{id}` 返回的 JSON 渲染（结构见 §5.4）。
2. **问题卡加"双数字对比"**：每张问题卡的慢放下方，增一行「标准 170° · 你 132°（差 38°）」，数据来自实测，强化"真测量"信任感。
3. **慢放/帧对比**：慢放视频用引擎切好的「我的这段」clip（`setpts` 或前端 playbackRate 0.25×）；帧对比两格 = 标准帧 + 我的帧并排（review-demo 已有 `.fc-grid` 结构，接真图）。
4. **情感维度视觉降级**：情感表达那格加小字「AI 观察 · 非测量」，或换成"眼神/神态"定性标签，不显示会误导的精确分。
5. **低置信态**：status=`low_confidence` 时，用整屏"建议重拍"卡替换报告主体（复用 toast/按钮）。
6. **接入舞镜主壳**：作为 `design-upgrade.html` 的一个结果页/路由（`?review=<id>`），沿用舞镜暖紫金 UI 变量，logo 保持「舞镜 · AI 点评报告」。
7. **底部动作按钮接线**：
   - 「按问题制定练习计划」→ `GET /api/plan/{review_id}`（已有端点，problems→每日专项任务）。
   - 「重新录制·再测一次」→ 回上传，若走 C 入口则把本次设为下次的标准。
   - 「发给老师·人工点评」→ 保留（人工兜底 + 未来变现）。
8. **技术脱敏检查**：全 UI 文案不得出现 MediaPipe/关键点/SSIM 等；统一「舞镜 AI 逐帧测量」。

## 五、后端要什么接口

复用现有 `server.py` + `auto_decompose.py` + `pose_angles.py`，**新增一个比对层 `review_compare.py`** 和三个/改造两个端点。

### 5.1 新增/改造端点
```
POST /api/solo/review
  入参:
    mode: "reference" | "self" | "progress"     # 三入口
    standard_id?: <decompose_id>                # A/C入口:已拆标准的id
    standard_video?: file                        # B入口:上传标准视频
    my_video: file                               # 必填:用户自己跳的
  行为: 建 review_id → 落 awaiting_payment 占位(付费墙复用) → 付费回调触发比对
  返回: {review_id, status:"awaiting_payment"|"processing"}

POST /api/solo/review/{id}/run   # 付费/额度校验后触发后台比对(照 decompose/run 模式)

GET  /api/solo/review/{id}       # 拉报告JSON(§5.4)，含 status: processing|completed|low_confidence|failed
GET  /api/solo/review/{id}/clip/{seg}    # 我的某段慢放切片
GET  /api/solo/review/{id}/frame/{pair}  # 标准/我的 对比帧
```
> 命名用 `/api/solo/*` 与旧 `/api/review/*`（老SSIM流）隔离，老端点不再对独舞线开放。

### 5.2 比对层 `review_compare.py`（新文件·核心）
```
run_solo_review(review_id, my_video, standard_ref, ...):
  1. 取标准分段角度:
     - A/C入口: 直接读 standard 的 decompose.json 里每段 angles(已缓存,免测)
     - B入口:   对标准视频跑 auto_decompose 的拆段+_run_pose 得每段标准角度
  2. 按标准的分段边界(bounds/BPM),对"我的视频"同样抽中帧+胶片帧
  3. _run_pose(我的每段中帧) → 我的每段实测角度
  4. 逐段逐关节做差 → 每段偏差字典 {right_elbow:{std,mine,delta}, ...}
  5. 节拍偏移: 我的段峰值帧时间 - 标准段峰值帧时间 → 折成拍
  6. 可测比例 < 40% → status=low_confidence, 不出总分
  7. 维度分/总分 = §3.1 规则(全实测,加权)
  8. 问题排序: 偏差最大的Top5 → problems[](含 std/mine/delta 真值)
  9. 亮点: 偏差最小的Top2段
  10. 文案: _vision_coach 变体,把每段真实差值喂进 prompt(禁空泛)
  11. 写 review.json + 存对比帧/慢放切片
```

### 5.3 复用清单（不重造）
- **拆段**：`auto_decompose.py` 的分段（`bounds`/`SEG_LEN`）、抽帧 `_grab`、切片 `_clip`。
- **测角度**：`pose_angles.py`（独立 mpvenv 子进程，`visibility≥0.55` 门槛，暗场重试）——**一字不改，独舞线和拆解共用**。
- **点评文案**：`_vision_coach` 的铁律 prompt（禁套话）+ `_fmt_angles`，加"标准 vs 我的差值"上下文。
- **付费墙**：复用 `/api/decompose` 的 awaiting_payment → pay.py 履约模式（免费额度门 + 境内支付商户，非 Stripe）。
- **练习计划**：`/api/plan/{id}` 直接吃 problems。

  "measured_ratio": 0.86,
  "score": 76,

### 5.5 成本/性能
- A/C 入口标准角度已缓存 → 仅测「我的」N 段（N≈5-10 帧姿态 + 1 次 vision 点评）≈ 拆解成本的一半。
- B 入口需拆标准，成本≈两次拆解，定价上可区分或引导用户走 A 入口（选平台已拆的当标准）。
- 姿态子进程模型只加载一次批量测；切片 `-c copy` 不重编码。

## 六、和现有拆解流程的关系（一句话收口）

## 八、诚实自评（本方案）

**方案要点总结**
- 定位：独舞点评 = 姿态引擎的"有参考"出口，与已上线"无参考拆解"共用引擎，只加"比对层"。
- 流程：三入口（老师对标 / 自带标准 / 进步曲线）→ 拆标准 → 测我的 → 逐关节+拍点做差 → 76 分报告。
- 诚实：弃用老 SSIM+随机模板；分数/角度/拍差全部姿态引擎实测；测不到就降级标注不编；情感维度诚实标"非测量"；低置信不出分改重拍。
- 前端：复用 review-demo.html，数据驱动化 + 加"标准vs你"双真值行 + 技术脱敏。
- 后端：新增 `review_compare.py` + `/api/solo/*`，复用拆段/pose/vision点评/付费墙，与旧 review 隔离。

**自评分：8.7 / 10**
- 加分：诚实红线落到引擎级（可回溯/降级/情感不装测/低置信重拍），与现有资产复用度高不重造，前端改动小，与拆解关系讲清。
- 扣分项（需 Karen/后续拍板）：
  1. 节拍偏移折算成"拍"需要 BPM，而 auto_decompose 现在 `bpm=None`（用固定分段），"提前1拍"要么先补 BPM 检测、要么先只报"提前约 X 秒"更诚实——建议 v1 先报秒。
  2. 单机位、用户与标准机位/景别不同会影响角度绝对值可比性；镜像一致性等相对指标更稳，"延展度"绝对角度差需做机位归一化或改报"相对趋势"，否则可能系统性偏差。
  3. 情感维度是否保留（哪怕标注非测量）还是直接砍，需 Karen 定——留着好看但有误导风险，砍了更硬核诚实。
```
