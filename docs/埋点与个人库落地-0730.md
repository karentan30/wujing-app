## 方案 ① PostHog 埋点方案

### 1.1 北极星 & aha & 习惯行为（先定义，事件都为它服务）

| 指标 | 定义（舞镜特有，别抄日活聊天） |
|---|---|
| **北极星 WAP**（Weekly Active Practicers） | 一周内至少完成 1 次「跟练 + 看点评」的用户数。**分母是跟练不是拆解**——拆解是一次性拉新，跟练才是留存。对应事件 `practice_complete` + `ai_review_viewed`。 |
| **Aha 时刻** | **第二次跟练同一支舞、且看到分数比上次高**。对应事件 `practice_repeat` + `score_improved`。onboarding 和拆解完成页的强引导，唯一目标就是把用户推到这一刻。 |
| **习惯行为（Habit Moment）** | **每周跟练 ≥ 2 次**（跳舞不是每天的事，周 2 次是爱好者健康频率）。用 PostHog 的 "performed event ≥ 2 times in 7 days" 定义留存队列。 |
| **激活（Activation）** | 注册 + 首支舞存进个人库 + 首次跟练完成。三步齐了才算真正激活（`register` → `work_saved_to_library` → `practice_complete`）。 |

### 1.4 留存怎么算（PostHog 里直接配，不用自建）

- **PostHog Retention 报表**：
  - **Start event** = `decompose_success`（Day1 首拆）
  - **Returning event** = `practice_complete`（不是「打开 App」——工具类按跟练算才真实）
  - 拆两个队列看：`from_class=true`（老师带班学员）单列，会显著高于自然 C 端，用来验证 B 端杠杆。
- **次日留存** = Day1 有 `decompose_success` 的用户里，Day2 有 `practice_complete` 或 `new_dance_from_lib` 的比例。
- **7 日留存** = Day1 用户在 Day2–7 内至少 1 次 `practice_complete` 的比例。
- **30 日留存** = Day1 用户在 30 天内 ≥ 2 次 `practice_complete` 的比例（工具类看「是否形成重复使用」比单次回访更真）。
- **北极星 WAP 面板** = Unique users where `practice_complete` performed ≥ 1 in last 7 days（周对周趋势）。
- **Aha 转化漏斗** = `decompose_success` → `practice_start` → `practice_complete` → `practice_repeat` → `score_improved`，看每步掉多少人，`留存设计 §3` 每周 1 小时就盯这个漏斗的「最后一步」。

## 方案 ② 个人库接线方案（登录后拆过的舞进「我的练习库」+ 每支舞进步曲线）

### 2.1 和现有拆解流程的关系（不重造，只补三处）

现状链路已经有 `user_id` 贯穿：`/api/decompose`（游客可传，登录则绑 `user_id`）→ 付费 → `run_decompose` 把 `user_id` 写进 `decompose.json`。**所以「入库」不需要新流程，只差一个「按 user_id 列出我的舞」的读接口 + 游客转登录时的回填 + 一张跟练分数历史表。**

三处改动：
1. **列表接口** `GET /api/my-works`：扫该用户所有 `decompose.json`（或建索引表），给「我的作品」页喂数据。
2. **游客→登录回填** `POST /api/claim-dance`：游客拆的舞（`user_id=None`），注册/登录后一键归属到自己名下（否则登录用户攒不到东西 = 个人库空）。
3. **跟练分数历史表** `practice_scores`：每次跟练存一条达标度，进步曲线的数据来源。

### 2.2 后端表结构（SQLite，跟现有 `pay.get_db()` 同库）

现有 `orders` 已在 `wujing.db`。新增两张表，跟着 `init_orders_table()` 一起初始化即可：

```python
# models.py 或 pay.py 里加，init 时调用
def init_library_tables():
    with get_db() as con:
        # ① 我的库索引（可选，性能优化；MVP 可先不建，直接扫 decompose.json）
        con.execute("""CREATE TABLE IF NOT EXISTS my_works(
            dance_id   TEXT PRIMARY KEY,
            user_id    INTEGER NOT NULL,
            title      TEXT,
            genre      TEXT,
            cover      TEXT,            -- frames/p1.jpg 相对路径
            duration_s REAL,
            n_phrases  INTEGER,
            is_paid    INTEGER DEFAULT 0,
            created_at TEXT DEFAULT (datetime('now')),
            expire_at  TEXT             -- 免费作品 7 天清理时间；付费=NULL(永久)
        )""")
        con.execute("CREATE INDEX IF NOT EXISTS idx_myworks_user ON my_works(user_id, created_at DESC)")

        # ② 跟练分数历史（★进步曲线的唯一数据源）
        con.execute("""CREATE TABLE IF NOT EXISTS practice_scores(
            id          INTEGER PRIMARY KEY AUTOINCREMENT,
            dance_id    TEXT NOT NULL,
            user_id     INTEGER NOT NULL,
            attempt_no  INTEGER NOT NULL,        -- 该舞第几次跟练
            score       REAL NOT NULL,           -- 本次达标度 0-100
            angles_json TEXT,                    -- 本次逐段角度快照(可选,做逐关节纠错)
            mode        TEXT,                    -- normal/slow/mirror
            created_at  TEXT DEFAULT (datetime('now'))
        )""")
        con.execute("CREATE INDEX IF NOT EXISTS idx_scores_dance ON practice_scores(dance_id, user_id, attempt_no)")
```

> 表设计要点：`my_works` 是**冗余索引**（数据源仍是 `decompose.json`，避免列表页 N 次读文件）。`practice_scores` 是**新的真数据**——现有系统只存了「拆解那一刻」的 `coach` 达标度，没存「用户每次跟练」的分数，进步曲线必须靠它。`attempt_no` 从 1 开始，`attempt_no≥2` 即 aha 事件 `practice_repeat` 的判定条件。

### 2.3 后端接口（三个，可直接加进 server.py）

```python
# ① 我的作品列表 —— 喂 my-works-demo.html
@app.get("/api/my-works")
def my_works(user: dict = Depends(get_current_user)):
    out = []
    with _pay_get_db() as con:
        rows = con.execute(
            "SELECT * FROM my_works WHERE user_id=? ORDER BY created_at DESC",
            (user["id"],)).fetchall()
    for r in rows:
        # 取该舞进步曲线（历次跟练分数）
        with _pay_get_db() as con:
            scores = con.execute(
                "SELECT score FROM practice_scores WHERE dance_id=? AND user_id=? "
                "ORDER BY attempt_no ASC", (r["dance_id"], user["id"])).fetchall()
        curve = [s["score"] for s in scores]
        out.append({
            "dance_id": r["dance_id"], "title": r["title"], "genre": r["genre"],
            "cover": f"/api/decompose/{r['dance_id']}/frame/p1",
            "duration_s": r["duration_s"], "n_phrases": r["n_phrases"],
            "is_paid": bool(r["is_paid"]), "expire_at": r["expire_at"],
            "curve": curve,                                    # [] = 还没练过
            "best_score": max(curve) if curve else None,
            "first_score": curve[0] if curve else None,
            "practice_count": len(curve),
        })
    return {"works": out, "count": len(out),
            "saved": sum(1 for r in rows if r["is_paid"])}

# ② 游客拆的舞 → 注册后归属自己（个人库能攒东西的前提）
@app.post("/api/claim-dance")
def claim_dance(data: dict, user: dict = Depends(get_current_user)):
    did = data.get("dance_id")
    d = get_decompose(did)
    if not d:
        raise HTTPException(404, "dance not found")
    if d.get("user_id") not in (None, user["id"]):
        raise HTTPException(403, "已归属其他用户")
    # 回写 decompose.json 的 user_id + 建 my_works 索引
    d["user_id"] = user["id"]
    with open(os.path.join(DATA_DIR, did, "decompose.json"), "w", encoding="utf-8") as f:
        json.dump(d, f, ensure_ascii=False, indent=2)
    _upsert_my_work(user["id"], d)          # 见下方 helper
    return {"status": "ok", "dance_id": did}

# ③ 提交一次跟练分数 —— 进步曲线写入 + aha 埋点
@app.post("/api/practice/{did}/score")
def submit_score(did: str, data: dict, user: dict = Depends(get_current_user)):
    score = float(data.get("score", 0))
    with _pay_get_db() as con:
        row = con.execute(
            "SELECT COALESCE(MAX(attempt_no),0) n, COALESCE(MAX(score),0) best "
            "FROM practice_scores WHERE dance_id=? AND user_id=?",
            (did, user["id"])).fetchone()
        attempt_no = row["n"] + 1
        prev_best = row["best"]
        con.execute(
            "INSERT INTO practice_scores(dance_id,user_id,attempt_no,score,angles_json,mode) "
            "VALUES(?,?,?,?,?,?)",
            (did, user["id"], attempt_no, score,
             json.dumps(data.get("angles")), data.get("mode", "normal")))
        con.commit()
    # 服务端埋点：练完 + 第二次练(aha) + 分数提升(价值兑现)
    from analytics import track
    track(user["id"], "practice_complete", {"dance_id": did, "attempt_no": attempt_no, "score": score})
    if attempt_no >= 2:
        track(user["id"], "practice_repeat", {"dance_id": did, "attempt_no": attempt_no})
    if score > prev_best and attempt_no >= 2:
        track(user["id"], "score_improved",
              {"dance_id": did, "prev_best": prev_best, "new_score": score, "delta": round(score-prev_best,1)})
    return {"attempt_no": attempt_no, "score": score, "prev_best": prev_best,
            "improved": bool(score > prev_best and attempt_no >= 2)}
```

`_upsert_my_work` helper（拆解完成时 & claim 时都调，把 `decompose.json` 冗余进索引表）：

```python
def _upsert_my_work(user_id, d):
    if not user_id:
        return
    did = d["id"]
    is_paid = _dance_is_paid(did)
    expire_at = None if is_paid else "datetime('now','+7 days')"  # SQL 里算
    with _pay_get_db() as con:
        con.execute(
            "INSERT OR REPLACE INTO my_works"
            "(dance_id,user_id,title,genre,duration_s,n_phrases,is_paid,expire_at) "
            f"VALUES(?,?,?,?,?,?,?,{ 'NULL' if is_paid else \"datetime('now','+7 days')\" })",
            (did, user_id, d.get("title"), d.get("genre"),
             d.get("dur"), len(d.get("phrases", [])), 1 if is_paid else 0))
        con.commit()
```

> 在 `run_decompose` 完成、且 `user_id` 非空时，调 `_upsert_my_work(user_id, result)` —— 这样**登录用户一拆完就自动进库**，无需额外动作。游客拆的等 `claim-dance` 回填。

### 2.4 前端接线（两个 mockup 怎么接）

**`my-works-demo.html`（我的作品）** —— 现在是写死 6 张卡 + 写死柱状高度。接线：

1. 页面加载 → `GET /api/my-works`（带 `Authorization: Bearer <wj_token>`）。未登录先弹登录（个人库是登录后能力）。
2. 用返回的 `works[]` 渲染卡片。每张卡：
   - 封面 `img.src = work.cover`。
   - 进步曲线柱状：把写死的 `<div class="b" style="height:X%">` 改成按 `work.curve[]` 动态生成，高度 = 分数值。`curve.length>=2` 才显示曲线，`curve.length==1` 显示「单次·再练一次解锁曲线」（正好对上 mockup 里免费卡的文案）。

   - 免费卡的「还剩 N 天清理」：`expire_at` 算天数；付费卡显示「已永久保存·会员」。

### 2.5 进步曲线的数据怎么记（端到端）

一句话：**达标度分数在跟练结束时产生 → 写 `practice_scores` → 按 `attempt_no` 排序即曲线。**

分数来源两条路，MVP 走前者：
- **MVP（现在就能做）**：拆解已有 `coach` 里的整支达标度，跟练完成时前端把「这次跟到第几段/播完」→ 复用拆解那次的达标度或让用户自评，先把 `attempt_no` 序列跑起来。曲线先有「回来练的次数」这个真信号。
- **完整版（挂订阅护城河）**：跟练时开摄像头，`pose_angles.py`（已存在，MediaPipe 子进程）逐帧算用户实时关节角度 → 和拆解里 `phrases[].angles`（原片标准角度）比 → 算本次达标度 `score`。这就是 PRD 第 8 项「实时摄像头角度纠错」，绑进 39/月订阅。`angles_json` 存本次逐段角度，可做「哪个关节没到位」的逐关节纠错。

曲线渲染：`my_works.curve = [第1次62, 第2次68, ..., 第N次92]`，前端柱状高度 = 分数。**第 2 根柱子出现的那一刻 = aha 兑现**，也是 `留存设计 §4` 北极星 WAP 的心跳。
