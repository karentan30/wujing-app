## 一、产品形态与核心流程（一句话）

**老师建班 → 生成班级邀请码 → 学员各自扫码加入并上传自己那段 → 舞镜AI逐个评分 → 自动汇总成班级报告（复用 report.html）→ 老师端一屏看全班、加评语、导出/分享。**

```
[老师端]                          [学员端]
建班(舞名/舞种/标准动作)
   │
   ├─ 生成6位班级码 + 二维码/链接 ──►  扫码/输码 加入班级
   │                                      │
   │                                   填昵称 → 上传自己那段(15-30s单人)
   │                                      │
   │  ◄──── 实时看"已交X/共Y" ◄──── 上传成功，进"等评分"
   │
   ├─ 全员齐 or 老师点"开始评分"
   │        │
   │   [后台队列] 逐人跑已有 /api/decompose 管线(舞镜AI评分+点评)
   │        │
   │   汇总：算全班排名/均值/雷达/统一短板/统一训练方案
   │        │
   ├─ 班级报告生成 ◄── 喂进 report.html 的 DATA 结构
   │
   ├─ 老师逐页加备注、改品牌、一键导出PDF/JPG、群发学员
   │                                      │
   └─────────────────────────────►  学员收到"我的个人页"(自己那页+班级排名)
```

**为什么"各自上传"而非"一段群舞自动分人"**（关键产品决策）：
1. 绕开多人检测硬伤，**评分质量稳定**（每段都是干净单人，走已验证的单人管线）。
2. **激活率天然高**：每个学员都要自己动手上传=每个学员都进App=B端签老师即批量拉新（护城河本质）。
3. 老师负担小：不用自己录全班、不用剪辑分人。
4. 群舞"合练同框视频"作为**可选补充**上传（仅展示用，不评分/或后续P2上多人检测），满足"群舞"仪式感。

## 二、老师端 · 需要什么

### A. 建班
- 表单：**舞名**（如《千年一顾》）、**舞种**（古典/敦煌/民族/爵士/K-pop…下拉，喂给评分话术+知识库）、**参考标准**（三选一：①传老师标准示范视频②选舞库现成③纯AI通用标准）、**班级人数上限**、**截止时间**（可选，到点自动锁定开评）。
- 建完即生成：**6位班级码**（易读，排除易混字符 0/O/1/I）+ **二维码** + **加入短链**（`wujing.mylumee.app/j/ABC123`）。

### B. 班级管理台（老师主界面）
- **进度看板**：已交 X / 共 Y，每个学员状态（未加入⚪ / 已加入待传🟡 / 已上传🟢 / 评分中🔵 / 已出分✅ / 失败⚠️可重传）。
- **催交**：一键复制邀请文案 / 对未交学员发提醒（走已有通知，无则复制链接手动发）。
- **开始评分**：全员齐自动触发，或老师手动"就这些人先出报告"（缺席的不阻塞）。
- **重跑单个**：某学员视频拍糊/检出差，老师可让其重传并单独重评（不重算全班积压）。

### C. 报告交付（= 现成 report.html，做实数据接入）
- 复用现有：班级总览页(排名表+雷达+总评+统一方案) + 每个学员独立tab页(六维meter+雷达+视频+背景切换+针对建议+老师备注)。
- 老师能做：**逐页加评语**（已有 contenteditable 自动存）、**改品牌**（Logo/机构名/老师名/标语，已有）、**打印/导出PDF**（已有）、**导出JPG长图群发**（新增，见五·前端）、**群发/生成每个学员的个人分享链接**（新增）。
- **机构品牌 = 护城河体验**：报告全程挂舞室Logo+机构名，家长看到的是"XX舞蹈学院的专业AI测评"，舞室拿它做招生/续费素材 → 舞室离不开 = 留存天花板。

### D. 历史与班级库
- 老师看历史班级列表（本月/本季）、同班多次测评的**纵向对比**（"上月S曲线1.1%→本月2.0%"），这是续费的核心说服力（家长看进步）。

## 三、学员端 · 需要什么（极简，3步内完成）

1. **加入**：扫码/点链接/输6位码 → 落地页显示"XX舞蹈学院 · 《千年一顾》班级测评" → 填昵称（+可选真实姓名给老师）→ 进班。免注册可先玩，上传前轻登录（手机/微信，防刷+归属，复用单人线登录）。
2. **上传**：清晰提示"**单人出镜 · 全身入镜 · 15-30秒 · 光线充足**"（直接决定检出质量，必须前置强提示，已有单人线文案复用）。带拍摄小样图/示范。上传中分步进度打勾（复用 `dcLoading`/`DC_STEPS`）。
3. **看结果**：出分后收到**自己那页**（六维分+雷达+针对建议+"班级第X名"）+ 老师评语。**只看自己+排名，不看别人明细**（隐私）。可一键保存分享图（带舞室品牌+舞镜水印=裂变）。

**学员端红线**：只展示自己的详情；排名表对学员端可做"隐名次序"（只显示自己高亮，别人可匿名或仅显昵称，由老师设置开关）。诚实标注"AI辅助评分，供训练参考"。

## 四、班级报告数据结构（前端怎么接）

现有 `report.html` 的 `DATA[]` 就是契约。产品化 = 后端出一个**班级报告JSON**，前端把写死的 `DATA` 换成 fetch。字段直接对齐现有页：

```jsonc
// GET /api/class/{class_id}/report  →
{
  "class": {
    "id": "cls_xxx", "danceName": "千年一顾", "genre": "敦煌舞",
    "brand": { "schoolName":"", "teacherName":"", "motto":"", "logoUrl":"" }, // 喂品牌区
    "createdAt": "...", "studentCount": 5,
    "classAvg": { "sCurve":1.5, "armHeight":74, ... },        // 班级均值→总评/雷达
    "commonWeakness": "S曲线(肩髋错位)全班均值1.5%…",          // 统一短板→总评
    "unifiedPlan": [ {step:"准备",min:2,desc:"…"}, … ]         // 统一训练方案(AI生成)
  },
  "students": [
    {
      "name":"张雨欣", "score":"5.2", "rank":1,
      "sc":{v:1.1,pct:"11%"}, "ah":{v:75,...}, "sp":{...}, "as_":{...}, "kn":{...}, "mv":{...},
      "radar":[11,75,50,62,70,48],
      "videoUrl":"…", "poster":"…", "bg":{…},                 // 复用视频卡/背景切换
      "fb":[["P0","S曲线—最需要攻克","…"], …]                  // 针对建议(AI生成)
    }, …
  ]
}
```

**前端改动清单**（在 report.html 基础上，不重写）：
- `DATA` 从写死改为 `fetch('/api/class/{id}/report')` 注入；加 loading/失败态。
- 品牌区从 localStorage 改为**优先用后端 brand**（老师建班时设过），localStorage 作离线兜底。
- 新增：**导出JPG长图**（html2canvas，每页/整份）、**学员个人分享页**（`/s/{token}` 只渲染该生那一页+排名）、**纵向对比视图**（同班历史）。
- 现有的六维meter/雷达/排名表/视频卡/背景切换/老师备注/打印全部原样保留。

**注意字段口径已固定**（S曲线满分10%目标≥6%、臂高满分100%目标≥80%、旋转满分20次、臂展满分0.5、屈膝1=直目标≤0.92、动作量满分0.3），后端评分输出必须按此归一，否则meter/雷达/颜色阈值全错。

## 五、后端要什么（接口 + 数据）

> 复用 FastAPI `/www/wujing-api`。群舞 = **建班/成员/上传归属 + 批量调度已有 decompose + 汇总**。核心评分能力已存在，本线主要是"编排层"。

### 数据表（新增，SQLite）
| 表 | 关键字段 |
|---|---|
| `classes` | id, teacher_uid, dance_name, genre, ref_video_id/mode, brand_json, invite_code(唯一,6位), max_students, deadline, status(open/scoring/done), created_at |
| `class_members` | id, class_id, student_uid/guest, nickname, real_name, join_at, status(joined/uploaded/scoring/scored/failed), decompose_id(挂到已有分析), score_json, rank |
| `class_reports` | id, class_id, version, report_json(汇总缓存), created_at |  ← 支持纵向对比多版本 |
| `teacher_subs` | teacher_uid, plan, seats, period_start/end, status |  ← B端订阅(见六) |

### 接口（新增编排层）
**老师端**
- `POST /api/class/create` — 建班，返回 class_id + invite_code + 二维码data。
- `GET /api/class/{id}` — 班级详情+成员进度看板（轮询/或SSE推）。
- `POST /api/class/{id}/start-scoring` — 触发批量评分（缺席不阻塞）。
- `POST /api/class/{id}/rescore-member` — 单人重跑。
- `GET /api/class/{id}/report` — 拉汇总报告JSON（喂前端）。
- `PATCH /api/class/{id}/brand` / `.../notes` — 存品牌/老师评语。
- `GET /api/teacher/classes` — 历史班级列表+纵向对比。

**学员端**
- `GET /api/join/{code}` — 校验班级码，返回班级品牌+舞名（落地页用）。
- `POST /api/class/{id}/member/upload` — 学员上传自己那段（内部转已有 `/api/decompose`，把 decompose_id 挂到 member）。**沿用单人线的额度门/类型+大小(500MB)校验/防刷**。
- `GET /api/class/{id}/member/{token}/result` — 学员看自己那页+排名（脱敏）。

### 调度与汇总（关键）
- **上队列**（P0，先补）：批量评分走 threading 池/队列，限并发（如≤4），防10人同传OOM。每人状态实时回写 `class_members.status`。
- **单人评分复用**：每个 member 就是调一次现有 decompose 管线（豆包vision+DeepSeek点评），拿六维分。
- **汇总层**（新写，纯计算+一次DeepSeek）：算排名(按主指标/综合)、班级均值、雷达、**统一短板识别**（找全班最差的公共维度）、**统一训练方案**（把班级短板喂DeepSeek出一份≈¥0.002）。全班5人总成本 ≈ 5×¥0.05(vision) + ¥0.002(方案) ≈ **¥0.25/班/次**，可忽略。
- **失败兜底**：某人检出差→标failed+可重传，不拖垮整班报告。

### 安全/合规
- 班级码防爆破（限流+错误延迟）；member 结果接口按 token 归属校验（别让A看到B）；上传鉴权门（堵白嫖）；报告页学员端脱敏。
- 全链路话术："舞镜AI辅助评分，供教学参考"，不出现底层技术名。

## 六、B端定价（舞室订阅 · 客单几百到几千）

> 定价逻辑：**按"班/席位"锁量，让舞室把它当招生/续费工具，而非按次计费的小工具**。成本可忽略(¥0.25/班)，定价锚在"省一次真人测评/招生素材"的价值，不锚成本。

### 主推：席位订阅制（年付为主，锁留存）
| 档 | 面向 | 含 | 月付 | **年付(主推)** |
|---|---|---|---|---|
| **体验版** | 试水老师 | 1班/月 · ≤10人 · 舞镜水印 · 基础报告 | ¥0（钩子·限1次） | — |
| **工作室版** | 单店小舞室 | 3个活跃班 · ≤60学员席位 · 去水印挂自有Logo · 导出PDF/JPG · 纵向对比 | ¥299/月 | **¥2,499/年**(省1189) |
| **机构版** | 中型舞校 | 10个班 · ≤200席位 · 多老师子账号 · 招生素材导出 · 优先评分队列 | ¥799/月 | **¥6,999/年** |
| **连锁/旗舰** | 连锁品牌 | 不限班 · 500+席位 · 白牌(换域名/全去舞镜标) · API/批量 · 专属客服 | 面议 | **¥15,000+/年** |

**为什么这样定**：
- **席位=续费锚点**：舞室有多少学员就买多少席位，学员越多越离不开（护城河量化）。
- **年付主推**：B端一年一签=留存天花板兑现；月付定高(年付≈月付7折)引导年付。
- **客单落在几百到几千**：工作室¥2,499 / 机构¥6,999 / 连锁¥1.5万+，覆盖题面区间。
- **白牌是连锁专属高价钩子**：连锁最在意品牌，白牌溢价大且反向加深锁定。

### 增值加购（拉高客单）
- **单次班级测评包**（未订阅或超额）：¥99/班（甜点价，试用转化）。
- **家长会/汇演季套餐**：旺季一次性测全校，¥1,999/次（对应"代烧=季节放大器"同思路，季节冲量）。
- **老师认证/培训**：舞镜AI教学法认证 ¥XXX（增强粘性+品牌）。

### 转化漏斗（B端GTM，配合护城河）
1. **免费体验1班** 引爆（老师亲手测一个班，看到家长惊艳反应）→
2. **家长看到品牌化专业报告** → 舞室拿去招生/续费 → 舖室体感到"这是我的招生武器" →
3. **年付席位订阅** 承接 → 学员批量进App=激活 →
4. **达人/舞室转介**（复用affiliate后台）："推荐同行舞室"给佣金/免费席位，B端裂变。

### 收款
- 复用 `支付集成方案-0730` 的下单/验签/幂等骨架，商品从"¥9.9一支舞"改为"订阅/席位包"。境内微信+支付宝(对公更佳)、境外Stripe。B端建议支持**对公转账+开发票**（舞室走账刚需，人工开通也行，别卡住成交）。

## 七、落地优先级（P0→P2）

**P0（最小可售闭环）**：建班+邀请码 → 学员各自上传(复用decompose) → 批量队列评分 → 汇总JSON → report.html 接真数据 → 老师导出PDF。定价先上"工作室版年付+¥99单次包"。
**P1**：进度看板实时/催交、学员个人分享页(裂变)、导出JPG长图、纵向对比、多老师子账号、对公+发票。
**P2**：一段群舞视频自动分人多人检测(补足"群舞同框"评分)、白牌连锁、API、旺季套餐自动化、健身版(AnyMotion)复用同架构。

## 八、风险与红线
- **检出质量**：靠"各自上传单人段+强拍摄提示"兜底；群舞同框自动分人不达标前不承诺，标"辅助/展示"。
- **合规诚实**：全程"AI辅助评分供教学参考"，不宣称替代老师、不承诺"精准/权威"。不暴露底层技术名（只说舞镜AI）。
- **隐私**：学员只见自己+排名；未成年学员数据（舞室多是儿童）需家长同意条款+最小化留存+可删除，B端合同里写清（儿童数据是硬红线）。
