# 舞镜 · 用户留存体系设计（0730）

> 作者角色：留存 owner（Growth）。老板要能落地的东西，不要看板套话。
> 前提事实（读过 PRD/mockup 确认）：舞镜是**工具类** H5，核心是"上传一支舞→AI拆成八拍卡/记忆卡/故事卡/慢放镜像跟练 + 角度点评"。定价 9.9/次或 39/月。已存在 `my-works-demo.html`（我的作品）和 `plaza-demo.html`（作品广场）两个 mockup——这两个是留存的地基，下面会重点用。
> 目前**没有埋点**（只在推广方案里提过 PostHog，未接线）。这是第一个要补的洞。

## 0. 一句话结论（老板先看这个）

- **最致命的死穴**：工具类的"用完即走"——用户拆完一支舞，成果它自己就是终点，**没有任何理由第二天回来**。而且成果是可下载带走的，用户拿完就彻底离线消费，我们连"他有没有练、练得怎么样"都不知道。
- **最高 ROI 的杠杆**：**登录后把拆过的舞沉淀成"我的练习库"+ 给每支舞一条"跟练进步曲线"**。把一次性产物变成"回来看自己变好"的资产。这是把工具粘住的唯一底层机制，其它杠杆都挂在它上面。
- **留存主要落在哪个职能**：**产品（60%）+ 内容/供给（30%）**，几乎不落在市场运营。舞镜不是"没人来"，是"来了留不住"。任何把留存问题甩给"多投放/多发小红书"的方案都是错配——那是拉新，不是留存。

## 1. 舞镜流失原因拆解表（照老板 Lumee 那套：为什么走 → 归哪个职能）

老板的方法论核心：留存本身无主，但**流失原因可以拆解归属**。下表就是把舞镜的"用完即走"拆成能派活的具体原因。**★=舞镜留存的命门格子，资源优先砸这里。**

| # | 用户为什么走（具体行为，不是抽象） | 发生在第几步 | 归哪个职能 | 优先级 |
|---|---|---|---|---|
| 1 | ★**拆完一支舞就没理由回来**——成果是终点，没有"下一次"的钩子；下载带走后完全离线 | Day1 用完即走 | **产品** | P0 |
| 2 | ★**看不到自己进步**——练了三天不知道有没有变好，没有跟练前后对比/分数曲线 | Day3-7 | **产品** | P0 |
| 3 | ★**拆过的舞找不回**——没登录/没个人库，昨天拆的今天翻不到，等于每次从零 | Day2 回访即流失 | **产品** | P0 |
| 4 | **拆解质量不达预期**——八拍分段错位、口诀空泛、动作描述对不上画面 | Day1 首拆 | **技术**（拆解引擎/vision） | P0 |
| 5 | **跟练时对不上**——慢放/镜像和音乐/自己动作不同步，节拍错位，跟着练很别扭 | Day1 首次跟练 | **技术**（librosa分段/播放器） | P0 |
| 6 | **实时角度点评不准**——摄像头骨架抖、角度数字明显错（"左肘68°"其实没错），失去信任 | 付费后首用 | **技术**（MediaPipe/pose） | P1 |
| 7 | **免费拆完不愿付 9.9**——免费已经够用（卡片全给了），付费墙给的角度分析感知不到价值 | 付费转化点 | **产品**（付费墙价值设计） | P1 |
| 8 | **没有"下一支想学的舞"**——拆完这支，舞库里没有他想学的下一支，断供 | Day3-7 复访 | **内容/供给**（舞库上新） | P0 |
| 9 | **一个人练很枯燥、没人看**——没有社交激励，练完无处炫、无人反馈 | Day7-14 | **运营/社区**（广场/打卡） | P1 |
| 10 | **老师/舞室没沉淀在里面**——学员上课用一次，课后老师没让他继续用，脱离课堂场景 | B端流失 | **运营/BD**（老师带班绑定） | P1 |
| 11 | **提醒缺失**——想练的时候没想起舞镜，没有任何召回触点 | 全周期 | **产品/运营**（提醒机制） | P2 |
| 12 | 首拆太慢/失败（上传大视频转圈久、偶发报错） | Day1 首拆 | **技术**（性能/稳定性） | P1 |

**读表结论**：
- **P0 全部落在「产品」和「技术/内容供给」**，没有一格落在市场运营。这验证了第 0 节的判断。
- 其中 **1、2、3 三格是同一个底层病**：产品没有"资产沉淀 + 进步可视"这一层。它们合起来就是死穴。**修好这三格，留存曲线会整体抬一个台阶。**
- 4、5 是"首拆体验"的技术质量。它们不直接是留存机制，但**是留存的地基**——拆得烂、跟不上，任何留存钩子都留不住人。所以技术侧 P0 = 保住首拆质量，产品侧 P0 = 建资产沉淀。

## 2. 把「单次工具」变「持续留存」的 5 个杠杆（每个：具体怎么做 + 影响哪条流失）

> 原则：工具类留存 = 制造"回来的理由"。理由有四种来源——**资产**（回来看我的东西）、**场景**（周期性有新的事要做）、**习惯**（提醒+成就把它变成日常）、**关系**（别人/老师让我不得不回来）。订阅是这四者成立后的收割。

### 杠杆 ① 沉淀资产：登录保存拆过的舞 = 个人练习库（最高 ROI，先做这个）
**怎么做（`my-works-demo.html` 已有 mockup，直接接线）：**
- 拆解产出**默认存进"我的舞库"**（不是拆完即弃）。首页永久有"我的作品"入口，进去是我拆过的所有舞的卡片墙。
- 每支舞卡片显示：拆解日期、跟练次数、最高分、最近练习时间。让用户**看到自己攒了多少舞**——攒得越多越舍不得走（沉没成本）。
- 免费用户也能存**元数据+卡片缩略**（原片 N 天后清理省磁盘，PRD 第10项已规划），付费长期存原片。
- 加"继续练"按钮：一键回到这支舞的跟练页，不用重新上传。

**影响流失**：直接杀 #3（拆过的找不回）、#1（用完即走——现在"我的库"就是回来的理由）。这是**其它所有杠杆的地基**，必须第一个做。

### 杠杆 ② 持续场景：给"回来"制造周期性事件
工具类要活，得让用户**每周都有一件新的事要做**。三条场景线：
- **(a) 每周学新舞**：舞库每周上新（PRD 六·补已定"每舞种每月上新10支"）。做一个"本周新舞"栏 + 首次注册可选 3 个想学的舞种，每周给他推 1-2 支对口新舞（弱推送，见杠杆③）。→ 影响 #8（没有下一支想学的舞）。
- **(b) 长期磨一支舞**：一支舞不是拆完就结束。建"跟练进度"——同一支舞每次跟练存一次角度点评/分数，形成**进步曲线**（第1次62分→第5次81分）。给用户"再练一次，把这支磨到90分"的目标。→ 影响 #2（看不到进步）、#1。
- **(c) 挑战/活动**：结合海外 K-pop 翻跳的"跳得和原版一样"心态，做"7天翻跳挑战"——每天跟练打卡，第7天出一支"进步合集"（第1天vs第7天对比片，天然可分享）。→ 影响 #9、#1。

**影响流失**：#8、#2、#1、#9。**(b) 进步曲线是这里的核心**，因为它把"工具"变成"教练"——教练是会让你持续回来的。

### 杠杆 ③ 习惯钩子：提醒 + 进度 + 成就
让跟练变成日常，而不是想起来才用：
- **练习提醒**：用户设了跟练目标（如"这周把这支练到80分"）后，给**轻量提醒**（H5 用邮件/后续 App 用推送；大陆合规注意，别做成骚扰）。触发点选在"他上次练习的同一时段"——命门是深夜/晚饭后练舞高峰。→ 影响 #11、#1。
- **进度可视**：个人库首页顶部一条"本周练了 X 支 / 连续打卡 X 天"，给连续性压力（断了可惜）。
- **成就徽章**：首拆、连续3天、把一支练到90分、拆满10支……**成就本身是资产**，进一步加沉没成本。别做花哨，做"和跳舞进步真相关"的成就（爱好者对"我变好了"的认证很买账）。

**影响流失**：#11、#1、#2。注意：习惯钩子**必须挂在杠杆①②之上**——没有资产和进步曲线，提醒就是骚扰。

### 杠杆 ④ 社交 + 课堂绑定：最强留存（尤其 B 端）
- **社交（C端）**：`plaza-demo.html`（作品广场）已有 mockup。让练得好的作品可发广场、可被点赞/打赏（PRD 已规划）。"练完有人看、被夸"是爱好者持续产出的最强动力。→ 影响 #9。
- **★课堂绑定（B端·最强留存，别只当付费方案看）**：老师带一个班用舞镜 = 全班**被动高频**使用。这是舞镜留存天花板最高的一条线，因为它把"个人要不要回来"变成"老师要求你每次上课/课后都用"。具体做法：
  - 老师建班 → 群舞逐人评分（已有）→ 学员**必须登录**领自己的分数和纠错 → 学员被动进入个人库体系（自动激活杠杆①）。
  - 老师布置"课后跟练作业"（指定一支舞，学员回家跟练交分数），老师看班级进度榜。→ 把课后复习场景锁死在舞镜里。
  - 一个老师 = 20-40 个学员的高频留存 + 天然拉新。**B端 owner 应把"每个活跃老师带回的月活学员数"当成核心留存杠杆指标。**

**影响流失**：#9、#10、#1、#3。**课堂绑定的 LTV/留存杠杆远大于 C 端单点**，早期 BD 拿下 10 个真用起来的老师，胜过投放几万曝光。

### 杠杆 ⑤ 订阅制：把 9.9 单次变月费的时机与设计
**时机（关键——别太早上订阅墙，会杀掉资产沉淀）：**
- 订阅只有在**杠杆①②成立后**才有意义。用户得先有"我的库 + 进步曲线"这些**持续用的理由**，月费才卖得动。没有持续场景就上月费 = 卖一个用一次的东西按月收，必退。
- **触发点驱动，不是首页硬推**：在用户**第3次拆解**或**第2次回访跟练**时（已表现出持续使用意图）弹订阅——"你已经拆了3支舞，39/月不限次 + 长期存 + 实时角度纠错"。转化率远高于对新用户硬推。

**设计：**
- **免费**：每月 1-2 次拆解 + 卡片 + 基础点评 + 个人库存卡片（钩子，让他攒起来）。
- **9.9 单次**：保留，给"只想拆这一支"的用户（如婚礼舞、一次性需求），是低门槛入口，也是订阅的对比锚点。
- **39/月订阅**：不限次拆解 + **实时摄像头角度纠错**（护城河功能，PRD第8项）+ 进步曲线长期保存 + 原片长期存 + 每周新舞优先。**把"持续用的功能"全绑进订阅**——续费理由 = 我的库和进步都在这。
- **B端班级版**：老师按班/月收，群舞逐人评分 + 班级进度榜。这是最健康的现金流（老师续费 = 全班续费）。

**影响流失/变现**：#7（付费不愿付——因为现在付费买的是"持续的进步系统"，不是一次分析）。**订阅本身就是留存的商业闭环**：付费用户的次月留存天然远高于免费。

## 3. 创始人每周 1 小时看什么（舞镜版最小诊断机制）

> 老板铁律：**先看真实行为，不看报表**。报表告诉你"死了"，行为告诉你"为什么死、在哪一步死"。每周固定 1 小时，Karen 亲自做，早期不授权。

**每周固定流程（看 30 个新用户就能看出模式）：**

1. **拉上周 30 个新注册/首拆用户的行为路径**（按 Day1/Day3/Day7 分组），逐个人看：
   - **首拆漏斗**：上传 → 拆解成功出卡 → 是否点开八拍卡 → 是否用过慢放/镜像跟练 → 是否分享/下载。**看他在哪一步之后不动了。**
   - **回访信号**：Day2/Day3 有没有再回来？回来是干嘛（看旧作品？拆新舞？没回来）？
   - **跟练信号**：有没有第二次跟练同一支舞？（第二次跟练 = 舞镜的真 aha，见第4节）
2. **重点盯"最后一个动作"**——每个流失用户最后做的那步是什么。如果 30 个里有 15 个"最后一步 = 拆完卡片就走、从没跟练"，那病在"卡片是终点、跟练没被激活"（产品）；如果 10 个"最后一步 = 点开跟练就退出"，那病在"跟练体验对不上"（技术 #5）。**同一个流失步骤重复出现 = 找到病灶。**
3. **亲自读 5 个流失用户拆出来的真实卡片**——拆解质量到底行不行？八拍对不对？口诀空不空泛？（这是报表永远看不出的，只能亲眼看产出物）。→ 判断是不是 #4 拆解质量在赶人。
4. **每周把病灶归到一格并派活**：按第1节的表，把本周最大流失原因派给对应职能（产品/技术/内容），下周复盘上周派的活有没有让那一步的流失下降。

**要能做到这个，第4节的埋点必须先接。** 没有埋点，这1小时就只能看后端 log 猜，看不清路径。

## 4. 核心留存指标与埋点（北极星 + 次/7/30日留存 + 关键事件）

### 北极星与 aha 时刻（舞镜特有，别抄"日活聊天"）
- **Aha 时刻**：**用户第二次跟练同一支舞并看到分数/角度变好**。第一次拆解只是"用了工具"；第二次回来练、且看到自己进步——这一刻他才理解舞镜是"能让我变好的教练"，而不是"拆一次的工具"。**所有 onboarding 和钩子都该把用户推向这一刻。**
- **习惯行为（Habit Moment）**：**每周至少跟练 2 次**（不是每天——跳舞不是每天的事，周2次是爱好者的健康频率，别照搬陪伴类日活）。
- **北极星指标**：**周活跃跟练用户数（WAP, Weekly Active Practicers）**= 一周内至少完成 1 次"跟练+看点评"的用户。不是拆解次数（拆解是拉新/一次性），跟练才是留存。

### 留存定义（工具类按"跟练"算，不按"打开"算）
- **次日留存**：Day1 首拆的用户，Day2 有"回访并发生一次跟练或拆新舞"的比例。
- **7日留存**：Day1 用户在 Day2-7 内至少回来 1 次并跟练的比例。
- **30日留存**：Day1 用户在 30 天内至少 2 次跟练的比例（工具类看"是否形成重复使用"，比单次回访更真实）。
- **B端单独算**：老师带班的学员留存单列（会显著高于自然C端，验证杠杆④）。

### 必埋的关键事件（最少这一套，按漏斗排）
```
拉新/首拆漏斗：
  upload_start          上传开始
  decompose_success     拆解成功出卡（含耗时、舞种、是否失败原因）
  cards_viewed          点开八拍卡/记忆卡/故事卡（分别埋）
  practice_start        进入跟练（慢放/镜像）
  practice_complete     完成一次跟练
  ai_review_viewed      看了AI点评/角度分数
  share_or_download     分享 or 下载带水印

留存/资产漏斗：
  register              注册（是否登录=能否沉淀资产的分水岭）
  work_saved_to_library 拆解存入个人库
  library_revisit       回访个人库
  practice_repeat       ★第二次跟练同一支舞（=aha，最重要）
  score_improved        ★同一支舞分数较上次提升（=价值兑现）
  new_dance_from_lib    从舞库拆下一支（持续场景生效）
  streak_day            连续打卡+1
  reminder_sent/clicked 提醒下发/点击

变现漏斗：
  paywall_shown         付费墙曝光（在第几次拆解时弹）
  subscribe_start / subscribe_success
  b2b_class_created     老师建班
  b2b_student_joined    学员领分数进班
```
**埋点铁律**：每个事件带 `user_id / dance_id / genre / is_paid / from_class(是否老师带班) / lang`，这样第3节的路径才能按分组切。PostHog（推广方案已提）接上即可，别自建。

## 5. 留存 owner 与职能分工

> 老板铁律：留存无主 → 必设专职 owner，早期只能是创始人本人，不授权。留存本身不可分配，但**流失原因按第1节的表拆解归属**。

| 角色 | 负责什么 |
|---|---|
| **留存 Owner = Karen（创始人，早期不授权）** | ①拥有北极星（WAP）和留存曲线；②每周1小时亲自看30个新用户行为路径（第3节）；③把当周最大流失原因归到一格并派活；④下周验证派的活有没有把那一步流失打下去。**owner 不是"做所有事"，是"诊断+分派+复盘"。** |
| **产品**（承接 #1/2/3/7/11） | 建个人库、进步曲线、成就/打卡、付费墙时机、提醒机制。**这是舞镜留存的主战场，产品拿最多留存活。** |
| **技术**（承接 #4/5/6/12） | 保住首拆质量：拆解引擎准、慢放/镜像同步、MediaPipe角度可信、上传性能稳。**技术不直接做留存机制，但守住留存地基。** |
| **内容/供给**（承接 #8） | 舞库每周上新、按用户想学舞种补供给、爆款舞及时入库。断供=复访断。 |
| **运营/BD**（承接 #9/10） | C端：广场/打卡活动/挑战赛运营；**B端：签老师带班（最强留存杠杆），把"活跃老师数×带回学员数"做成运营KPI。** |
| **市场**（几乎不碰留存） | 只负责拉新。**明确：留存问题不派给市场。** 见到"多投放/多发内容"来答留存的方案，判为错配打回。 |

**分派机制**：每周诊断后，Karen 用一句话把病灶派出去，例如——"本周30个里18个拆完从不跟练 → 产品：把'跟练+看进步'做成拆解完成后的强引导下一步，下周看 practice_start 转化率有没有从X%涨上来。"

## 6. 最先做的 3 件事（按 ROI 排序，早期资源有限）

**第 1 件：接埋点 + 建个人库（同一批做，因为互相依赖）** 🔴最高优先
- 接 PostHog，埋第4节那套关键事件（尤其 `practice_repeat` / `score_improved` / `work_saved_to_library`）。**没这个，第3节的每周诊断和整个留存优化都是盲人摸象。**
- 接线 `my-works-demo.html` → 拆解默认存入"我的舞库"，首页常驻入口。
- **为什么第一**：埋点是所有诊断的前提；个人库是所有留存杠杆的地基（杠杆①，直接杀死穴 #1/#3）。这两件不做，后面全悬空。

**第 2 件：给每支舞做"跟练进步曲线" + 把 aha 拉到前面** 🟠
- 同一支舞每次跟练存一次分数/角度点评，展示"第1次62→第5次81"的曲线。
- 拆解完成后的**强引导下一步 = "现在跟练一次，看你的起始分"**，把用户推向"第二次跟练看到进步"这个 aha（第4节）。
- **为什么第二**：这是把"工具"变"教练"的那一下，直接影响北极星 WAP 和 7/30 日留存。挂在第1件的个人库之上。

**第 3 件：签下 5-10 个真用起来的老师（B端课堂绑定）** 🟡
- BD 出去，让老师用群舞评分带班 + 布置课后跟练作业，学员被动进个人库体系。
- **为什么第三而非第一**：ROI 单点最高（一个老师=几十个高频学员），但依赖第1、2件把 C 端底座（个人库+进步曲线）先搭好，学员进来才有东西留。且 BD 是人力密集、见效稍慢，所以排第三、马上并行启动。

> 三件事的逻辑链：**先能看清（埋点）+ 先能沉淀（个人库）→ 再让用户体验到进步（曲线/aha）→ 再用老师把留存规模化（课堂绑定）。** 不要跳步：没有前者，后者留不住人。
